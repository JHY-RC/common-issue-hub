# 共性问题/需求管理平台

本地使用的版本分支与共性/需求问题管理工具。现阶段以“版本、分支、共性事项”为核心，机台型号数据暂时保留但不参与判断。

## 当前功能

- 管理软件产品、版本号、所在分支和父版本关系
- 为问题记录发生版本，为需求记录提出版本
- 同一个问题或需求可在主线和多个维护分支分别登记修复 / 实现版本
- 选择准备迭代的目标版本，查看未修复问题和未添加需求
- 展示其他分支已有的修复版本，以及该修复分支当前录入的最新版本
- 子版本只继承真实父版本链上的修复；并行分支不会因版本号更晚而误继承
- CSV 导出备份

## 启动

双击 `启动平台.bat`，浏览器将打开 `http://localhost:4170`。运行所需组件已随项目放在 `runtime` 文件夹中，请勿删除。首次使用请先建立产品和起始版本，再创建后续主线或维护分支。

数据保存在 `data/common-issues.db`。定期使用页面右上角“导出备份”保存 CSV；复制该数据库文件也可完整备份。

## 代码结构

后端采用 MVC 分层，网页文件保持在 `public/`：

- `src/routes/`：接口路由
- `src/controllers/`：请求处理与响应组织
- `src/services/`：版本继承、分支判断和迭代评估规则
- `src/repositories/`：数据库读写
- `src/database/`：数据库连接与初始化
- `src/utils/`：校验、CSV 和版本号比较等通用能力

启动入口 `server-v2.mjs` 只负责创建和启动应用服务。

## 使用规则

1. 创建新版本时，必须选择真实的父版本和所在分支。
2. 录入共性事项时，问题填写首次发生版本，需求填写开始提出 / 需要跟踪的版本。
3. 某事项在不同分支分别完成时，分别添加对应的修复 / 实现版本。
4. 在“迭代评估”选择目标版本。只有位于目标版本祖先链上的修复才算已经进入目标版本。

> 系统不会根据版本号大小猜测继承关系。版本号晚于另一个版本，也不代表自动包含其修复。
>
> “发生 / 提出版本”决定事项从哪个版本开始进入产品待办池。早于该版本的开发基版不会显示该事项；达到或晚于该版本后，只要开发基版的祖先链中没有对应修复 / 实现版本，就会显示为未完成。
